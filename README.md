HRSYSTEM — СИСТЕМА КЕРУВАННЯ ПЕРСОНАЛОМ ТА ПОГОДЖЕННЯ КАДРОВИХ ЗАЯВОК

Github: https://github.com/vo366333-hub/HrSystem

1. ПРИЗНАЧЕННЯ ПРОГРАМИ

HrSystem є настільним програмним застосунком для автоматизації кадрового обліку, керування організаційною структурою, робочими графіками та двоетапного погодження кадрових заявок працівників. Програму розроблено мовою C# на платформі .NET із використанням принципів об'єктно-орієнтованого програмування, графічного інтерфейсу Windows Forms та локального збереження даних у форматі JSON.

2. ОСНОВНІ ФУНКЦІОНАЛЬНІ МОЖЛИВОСТІ

1) Облік працівників та кадрових змін:
   Додавання нових працівників із зазначенням ПІБ, посади, підрозділу, робочого графіка, дати прийняття та стартового балансу оплачуваної відпустки;

   Переведення працівника між підрозділами, зміна посади та робочого графіка;

   Керування статусом активності (неактивний працівник не може подавати нові кадрові заявки);
   Оформлення незворотного звільнення працівника із фіксацією дати, причини та відповідальної особи, автоматичним скасуванням усіх його незавершених заявок і блокуванням подальшого редагування картки.

2) Керування підрозділами та робочими графіками:
   Ведення довідника підрозділів із зазначенням керівника, опису та автоматичним підрахунком кількості працівників;
   Створення й облік робочих графіків (стандартний 5/2, скорочений, гнучкий, змінний графік 2/2) із заданням годин роботи, тижневого навантаження та робочих днів;
   Автоматичний підрахунок робочих днів і змін за графіком працівника для будь-якого періоду заявки.

3) Поліморфна обробка кадрових заявок трьох типів:
   Відпустка (VacationRequest): підтримка щорічної оплачуваної, навчальної та відпустки без збереження заробітної плати, перевірка достатності залишку днів, зазначення особи, що заміщує, та автоматичне списання днів після фінального затвердження відділом кадрів;
   Лікарняний (SickLeaveRequest): фіксація номера медичного висновку (е-лікарняного) та режиму лікування (амбулаторно або стаціонар) без списання днів щорічної відпустки;
   Відрядження (BusinessTripRequest): зазначення міста, мети поїздки, ставки добових та автоматичний розрахунок загальної суми добових витрат.

4) Правила погодження, контроль конфліктів та журнал аудиту:
   Двоетапна машина станів погодження (ApprovalWorkflow): Подана -> Погоджено керівником -> Затверджено HR, а також переходи у статуси Відхилено (з обов'язковим зазначенням причини) та Скасовано;
   Заборона обходу етапу погодження керівником підрозділу та блокування редагування заявок у фінальних статусах;
   Автоматична перевірка перетину дат із уже активними заявками того самого працівника;
   Незмінний журнал історії погодження кожної заявки з датою, часом, зміною статусу, автором дії та коментарем;
   Нахищене видалення (дозволено видаляти лише подані, відхилені або скасовані заявки; погоджені та затверджені зберігаються для обліку).

5) Пошук, фільтрація, статистика та збереження даних:
   Фільтрація заявок за статусом, типом, підрозділом та миттєвий пошук за ПІБ, підставою, містом чи номером медвисновку;
   Верхня панель оперативної статистики та колірне виділення статусів заявок і працівників;
   Локальне збереження у JSON-файл через окремий DTO-шар з атомарним перезаписом через тимчасовий файл та обробкою помилок пошкодження файлу.

3. СТРУКТУРА РІШЕННЯ ТА АРХІТЕКТУРА

Програмне рішення HrSystem.sln розділене на чотири окремі проєкти, що забезпечує повну незалежність бізнес-логіки від графічного інтерфейсу та механізму збереження даних:

1) HrSystem.Core (бібліотека класів):
   Enums: переліки статусів заявок (RequestStatus) та видів відпусток (VacationType);
   Exceptions: доменні винятки (HrDomainException, InvalidApprovalTransitionException);
   Models: класи Department, WorkSchedule, Employee, RequestHistoryEntry, абстрактний базовий клас HrRequest та його нащадки VacationRequest, SickLeaveRequest, BusinessTripRequest;
   Workflow: статичний клас ApprovalWorkflow із матрицею допустимих переходів;
   Interfaces: контракт сховища IHrRepository та структура даних HrData;
   Services: сервіс HrService, параметри фільтрації RequestFilter та статистика HrStatistics.

2) HrSystem.Storage (бібліотека класів):
   Dto: класи передачі даних HrStorageDtos та перетворювач HrStorageMapper для поліморфної серіалізації без порушення інкапсуляції домену;
   JsonHrRepository: реалізація IHrRepository з атомарним записом у JSON та підтримкою кирилиці;
   Seed: генератор початкового демонстраційного набору даних SampleHrDataSeeder.

3) HrSystem.UI (застосунок Windows Forms):
   Forms: головне вікно MainForm із трьома вкладками, форма подання заявки CreateRequestForm, картка погодження RequestDetailsForm, діалог працівника EmployeeDialogForm, діалог оформлення звільнення;
   UiDisplayHelper: локалізація переліків та днів тижня українською мовою;
   Program.cs: точка входу, налаштування шляху сховища, ініціалізація залежностей та обробка помилок запуску.

4) HrSystem.Tests (проєкт модульного тестування xUnit):
   InMemoryHrRepository: ізольоване сховище в пам'яті для перевірки ядра;
   HrDomainAndServiceTests: перевірка робочих графіків, балансу відпусток, перетину дат, правил погодження, звільнення, фільтрації та статистики;
   JsonHrRepositoryTests: перевірка збереження й відновлення поліморфних типів у JSON та обробки пошкодженого файлу.

4. СИСТЕМНІ ВИМОГИ ТА ЗАЛЕЖНОСТІ

Операційна система: Windows 10 або Windows 11 (64-bit).
Платформа виконання: .NET SDK 8.0 або новішої версії (для запуску скомпільованої версії достатньо .NET Desktop Runtime 8.0+).
Середовище розробки (рекомендовано): Microsoft Visual Studio 2022 або новіше з компонентом .NET desktop development.
Залежності основних проєктів (Core, Storage, UI): використовуються лише стандартні бібліотеки платформи .NET (System.Text.Json, System.Windows.Forms), сторонні зовнішні бібліотеки не потрібні.
Залежності проєкту тестування (HrSystem.Tests): NuGet-пакети xunit, xunit.runner.visualstudio та Microsoft.NET.Test.Sdk (відновлюються автоматично під час збірки).

5. НАЛАШТУВАННЯ ТА КОНФІДЕНЦІЙНІ ДАНІ

Застосунок працює повністю локально і не потребує підключення до зовнішнього сервера бази даних, мережі Інтернет, паролів, токенів або секретних ключів доступу.
Усі дані зберігаються локально у файлі Data\hr_data.json відносно каталогу розташування виконуваного файлу програми (наприклад, HrSystem.UI\bin\Debug\net8.0-windows\Data\hr_data.json).
Каталог Data та файл сховища створюються автоматично під час першого запуску програми. Додаткового ручного налаштування перед запуском не потрібно.

6. ІНСТРУКЦІЯ ЗАПУСКУ ПРОГРАМИ

Спосіб 1. Запуск через Microsoft Visual Studio:
1. Відкрийте файл рішення HrSystem.sln у Visual Studio.
2. У вікні Solution Explorer клацніть правою кнопкою миші по проєкту HrSystem.UI та оберіть пункт Set as Startup Project.
3. Виконайте повну збірку рішення через меню Build -> Rebuild Solution (або комбінацією клавіш Ctrl + Shift + B).
4. Запустіть застосунок через меню Debug -> Start Without Debugging (Ctrl + F5) або Start Debugging (F5).

Спосіб 2. Запуск через командний рядок (.NET CLI):
1. Відкрийте термінал (PowerShell або Command Prompt) у кореневому каталозі проєкту, де знаходиться файл HrSystem.sln.
2. Послідовно виконайте такі команди:
   dotnet restore
   dotnet build
   dotnet run --project HrSystem.UI

Спосіб 3. Запуск скомпільованого виконуваного файлу:
1. Перейдіть до каталогу збірки (наприклад, HrSystem.UI\bin\Release\net8.0-windows або Debug).
2. Запустіть файл HrSystem.UI.exe (переконайтеся, що на комп'ютері встановлено відповідну версію .NET Desktop Runtime).

7. ТЕСТОВІ ДАНІ ДЛЯ ДЕМОНСТРАЦІЇ

Під час першого запуску (якщо файл Data\hr_data.json відсутній або порожній) автоматично виконується SampleHrDataSeeder, який створює демонстраційний набір даних:
- 3 підрозділи (Відділ розробки ПЗ, Відділ технічної підтримки, Бухгалтерія та фінанси);
- 3 робочі графіки (Стандартний 5/2, Гнучкий 5/2 скорочений, Змінний 2/2);
- 5 працівників (4 активних і 1 неактивний) із різними балансами оплачуваної відпустки;
- 6 кадрових заявок усіх трьох типів (Відпустка, Лікарняний, Відрядження) у всіх п'яти статусах життєвого циклу.

Для скидання програми до початкового демонстраційного стану необхідно закрити застосунок, видалити файл Data\hr_data.json у каталозі запуску та відкрити програму повторно.

8. ЗАПУСК АВТОМАТИЗОВАНИХ ТЕСТІВ

Для перевірки успішних та помилкових сценаріїв бізнес-логіки й JSON-сховища скористайтеся одним із способів:

1) У Visual Studio: оберіть у верхньому меню Test -> Run All Tests (або комбінацію клавіш Ctrl + R, A) та перегляньте результати у вікні Test Explorer.
2) Через командний рядок у кореневій папці рішення виконайте команду:
   dotnet test

9. ОБМЕЖЕННЯ ТА НАПРЯМИ ПОДАЛЬШОГО РОЗВИТКУ

Поточна версія розрахована на локальну однокористувацьку роботу з файлом JSON без системи облікових записів. Завдяки розділенню архітектурних шарів та використанню інтерфейсу IHrRepository систему можна розширити без зміни ядра HrSystem.Core: додати збереження в реляційну СУБД (SQLite або PostgreSQL), реалізувати клієнт-серверний режим із розмежуванням ролей (працівник, керівник, HR-адміністратор) та експорт кадрових наказів і табелів у формати PDF або Excel.
